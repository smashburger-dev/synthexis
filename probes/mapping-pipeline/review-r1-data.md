 At most 12 findings, ordered by damage on real traffic. No praise, only breakage.

**1. [HIGH] `prompts/commands.md: Output - Mark every slot except i1` + `DESIGN.md: Filters - mark validator` - polarity silent error**
*Problem:* 15% of `map` routes have `i1` (invert). Prompt says leave `i1` unmarked if carried by construction (`"the more I close, the darker"`). Validator checks `every marked slot appears exactly once` - `i1` is exempt. If Spark writes `"the more I close, the brighter"` (wrong polarity) or drops contrast entirely, validator passes. At 22k `map` sents ~3.3k inverted, ~1.6k have no lexical invert signal. Parser trained on contradictions learns `invert` is random noise; `d=-1` from `label.md` (Dry/Damping/Threshold/Bits) then doubles error at resolver.
*Fix:* Remove exception. Require `i1` always marked: `[[inverted|i1]]`/`[[umgekehrt|i1]]`/`[[the other way|i1]]`. Add polarity lexicon validator: if `edit.i1==1` sentence must contain one of `invert|reverse|umgekehrt|andersrum` or antonym pair for that source/target (`close<->bright` ok, `close<->brighten` not). Reject else. Cost: string match.

**2. [HIGH] `prompts/commands.md: Output - Marks never nest` + `DESIGN.md: Augmentation - span substitution` - hallucinated unmarked concepts**
*Problem:* Validator is positive-only. Edit `s1->t1` can be realized as `[[right fist|s1]] -> [[reverb|t1]] plus a bit of chorus on [[pad|k1]]` - extra `chorus` (=`fx.mod.mix`) unmarked, validator passes. Same for `both hands` when edit has single side. Augmentation then multiplies these by glossary substitution without re-validation. Parser learns to ignore second source/target mention. Real `"fist -> reverb + delay"` -> drops one target.
*Fix:* Negative lexicon check: flag sentence if it contains any glossary phrase for a source/taxonomy not in edit (hashed char n-gram vs glossary). Reject or route to blind round-trip. Re-run validator after augmentation.

**3. [HIGH] `edits.yaml: styles.register terse15 polite8 rambling7` + `prompts/commands.md: How to write - vary structure` - no fragment supervision**
*Problem:* LLM with bracket markup always produces grammatical verb-mediated sentence (`X controls Y`). Real Discord typing is keyword soup: `pad verb fist`, `bass cutoff mouth 20-70%`, `fist->verb pad`, no verb, order free. `terse` 16% of corpus still has verbs. Parser over-weights verb token as intent feature; auxiliary BIO never sees zero-verb spans. Fails on most terse queries.
*Fix:* Add `styles.register.keyword:20` generated by template not LLM: shuffle `[track] [param] [source] [range]` with `-> , / |` separators, no verb. New distribution: `casual28 terse20 jargon12 beginner12 keyword20 polite4 rambling4` (=100). Noise `typos` must be allowed inside marks (see #9).

**4. [HIGH] `edits.yaml: routes_per_edit 1:60 2:30 3:10` + `scope` + `prompts/commands.md: Mark every slot exactly once` - no ellipsis/anaphora**
*Problem:* Every synthetic route spells every argument every time. Real multi-route: `fist to reverb on pad, also delay there`, `same for bass`, `make it less`. With `variants_per_edit:2` both are full sentences, never pronominal. Model learns `track` slot always lexicalized. Real `"add delay on same track too"` -> `there/same` tagged `O` or as track name, resolver defaults to `none:15%` or wrong channel.
*Fix:* Add `scope: anaphoric` 30% of 2nd/3rd routes in edit. Realization must use pronoun from list `there|same track|auch dort|ebenda` marked as `[[there|k1]]`. Generate via template for half of those.

**5. [HIGH] `ontology.yaml: taxonomy filter.cutoff vs fx.tone vs fx.eq.freq` + `prompts/label.md: Rules para 2-3` - systematic class error**
*Problem:* Harvest gives only `group path > name | unit | values`. Prompt says `filter.cutoff only for real filter section, Tone/Damping/HiCut inside reverb is fx.tone`. LLM has no `plugin type` feature, sees word `Cutoff` in `Reverb > Hi Cut` and labels `filter.cutoff`. Same for `EQ band freq` vs synth filter. ~30% of `fx.tone` will leak to `filter.cutoff`, safe range `[0.05,1]` vs `[0,1]` propagates, resolver can't distinguish reverb damping from synth cutoff.
*Fix:* Add to input header `AU type: instrument|reverb|delay|mod|distortion|eq` from harvest. Add hard rule + 5 examples to prompt: `if plugin is reverb/delay/dist and group contains Reverb|Delay|Color|Tone then Cutoff/Damp/HiCut => fx.tone not filter.cutoff`.

**6. [HIGH] `edits.yaml: params` weights at 40k sents - rare classes starved**
*Problem:* 40k sents = 20k edits ×2. `map`55% × avg1.5 routes×1.3 targets = ~17k param targets training (not 36k - `targets: param85%` already). `fx.eq.q 0.7/139=0.5%` => ~85 ex total, split en/de/styles => ~4 per style, 0 with `range`. `other 0.5`, `fx.eq.freq1.5`, `fx.gate1.5` similar. `midi.cc1%` => ~220 ex. Vendor holdout for `param-sense` will be random on those; parser never learns `other/unsafe` boundary.
*Fix:* Cap dominants, floor tails for first dataset: `filter.cutoff14->8, fx.reverb.mix12->7, amp.gain8->5`, raise `fx.eq.q0.7->2.5, fx.eq.freq1.5->3, fx.eq.gain2->3, fx.gate1.5->3, other0.5->2, unsafe1.5->3, fx.comp.amount2->3`. Targets: `param85->70, macro5->9, midi.note4->6, midi.pattern3->6, midi.chord2->5, midi.cc1->4`. Gives every mappable class >300 ex at 40k.

**7. [MED] `edits.yaml: languages en60 de40` + `prompts/commands.md: German` - translationese**
*Problem:* LLM prompted in English writes High German with English nouns (`die Reverb`). Real German producers use Denglisch verb morphology `mappen, auf den Pad mappen`, bare English fragments `pad verb fist`, `ae/oe/ue` inconsistency. `say_probability0.5` inflects glossary but LLM regularizes. Parser learns `Reverb` only after German determiner, fails on code-switch.
*Fix:* First dataset `languages en75 de25` (Noa's 100 is EN-heavy, DE tails still learn). For DE, 50% generate by EN template + German track/source swap, not LLM. Add verb glossary `mappen, routen, layern`.

**8. [MED] `edits.yaml: scope none30 track45 plugin10 track_plugin10 param_name5` + `fl_plugins` list - resolver never trained**
*Problem:* Plugin-bearing mentions 20% total, `param_name`5%. Resolver's hardest job (fuzzy `Fruity Reeverb2` vs `Valhalla`) seen minority; literal name bypass for `mappable=false`/`unsafe` (`+12dB output, Bypass, Program`) needs `param_name` but gets ~15 sents total (`5%*1.5% unsafe`). Also `fl_plugins` contains `Vital, Serum` misfiled as FL natives, contaminates distribution.
*Fix:* `scope none15 track33 plugin20 track_plugin20 param_name12`. Remove `Vital, Serum` from `fl_plugins`; keep 50/50 FL vs harvest as designed.

**9. [MED] `edits.yaml: noise typos12 dictated13` + `prompts/commands.md: typos outside marks` - clean-span bias**
*Problem:* Rule `typos outside marks` guarantees entity spans (`reverb, cutoff, pad, Fruity Delay 3`) are always clean. Dictated `no punctuation maybe uh` has perfect spelling, no STT homophones `to/two, filter/fillter`. Char n-gram embedding learns `clean=>entity`. Real typo `reeverb, cutof, reverv` -> BIO `O`.
*Fix:* Allow 10% typo rate *inside* marks (1-char swap/del on marked span, keep alignment). For `dictated` 20% apply STT error list (`lowercase, s->ß, missing umlaut`). Validator: allow 1-edit distance for mark text.

**10. [MED] `prompts/label.md: Task 3 lo,hi` + `Rules: look at 100% value` - LLM arithmetic**
*Problem:* `lo,hi` requires interpolating where value hits `0dB` or self-oscillation between `0/20/50/80/100%` samples, log dB scale. Prompt gives vague caps `resonance ~0.8, feedback ~0.85, gain at most 0dB, cutoff from ~30Hz`. LLM will miscompute `+6dB at 80% => hi~0.65` as `1.0`. `unsafe` defined as `far above 0dB` no threshold - `+6` vs `+12` inconsistent.
*Fix:* Don't ask for float interpolation. Ask LLM to pick bin `0,0.2,0.5,0.8,1` nearest to `0dB` point. Define: `if value at 100% > +3dB or at 80% > +6dB => unsafe, hi= where 0dB bin`. Provide table `Dry/Damping/Threshold/Bits/Bandwidth => d=-1` explicitly, ignore displayed order for those.

**11. [MED] `prompts/label.md: macro` rule - meaningful vs generic**
*Problem:* `Brightness->fx.tone, Macro3->macro` distinction is subjective. Synths label macros `Time, Color, Space` - is that meaningful? Producers rename macros `My Verb #014`. LLM inconsistent; harvest shows `#014` but user project shows renamed. `param-sense` trained on noisy `macro` labels predicts `fx.*` for generic macros, fails in FL where macro is the only addressable target.
*Fix:* Replace subjective rule with regex in prompt: `if name matches ^(Macro|Knob|Quick|M\d+|#\d+|CC\d+)\b` case-insensitive => `macro` else label by meaning. Add 10 positive/negative examples.

**12. [LOW] `DESIGN.md: Build 2 Labels - template dedup + two passes temp0.2/0.7 reversed` + `edits.py: edits_per_job20` - propagation + leakage**
*Problem:* Bulk `template dedup` collapses `Mix` across delay/distortion/reverb - one wrong label propagates to hundreds of plugins. Double-pass with same model reversed order not independent; systematic `filter vs tone` agrees both times, adjudication `with reasoning` by same model confirms itself. `edits_per_job20` packs 20 edits in one LLM call - LLM bleeds phrasing (`reverb` wording for `delay` edit) but each edit still has correct marks count, so validator blind; blind round-trip only on `sample`.
*Fix:* Dedup only within `same AU type + vendor`. `edits_per_job 20->8`. For priority plugins adjudicate by different prompt (show conflicting class pair only) or 100-param human stratified audit: 20 each rare class `macro/other/unsafe/fx.eq.*` report Wilson CI per class, not just overall.
